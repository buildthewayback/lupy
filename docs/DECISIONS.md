# Architecture, licensing and runtime decisions

Status vocabulary: `ACTIVE`, `PROPOSED`, `SUPERSEDED`. Reversibility: Easy / Moderate / Hard.

| ID | Decision | Rationale / evidence | Status | Reversibility |
|---|---|---|---|---|
| D-001 | Work on branch `arena/48b1c2c3-lupy` of private repo `toastmangoapp-cloud/lupy`; never push `main`; never touch Coucou upstream. | Session is fixed to this branch; directive §11. | ACTIVE | Easy |
| D-002 | Lupy is a **new app** that adapts selected Coucou code (MIT) — island/notch panel, shapes, card/button styles, theme palette, Keychain pattern, Canvas animation technique — rather than a full fork of Coucou's 48k-line app. | Coucou's features (Claude Code hooks, music, crypto, phone link, local Parakeet model) are not Lupy's product; a full fork would carry ~40k lines of unrelated code, its author's signing team, and reserved assets entangled throughout. Adapting the visual language keeps the familiar look at a fraction of the risk. See COUCOU_REUSE_MAP.md. | ACTIVE | Moderate |
| D-003 | **Functional core / imperative shell.** `LupyCore` = stdlib-only Swift (no Foundation): state, events, policy, verification, planning, priority, scheduling, providers (request building/parsing), budgets, connectors (parsing), engine. The macOS app = SwiftUI/AppKit shell that executes effects (HTTP, Keychain, files, notifications, speech). | The only compiler reachable from the sandbox is Swift-on-WASM without Foundation (WP-0). Stdlib-only core ⇒ every business rule is compiled and tested here at 0 Actions minutes; the shell stays thin. Also gives deterministic, injectable clock/IDs/storage for recovery tests. | ACTIVE | Hard |
| D-004 | Persistence = **append-only JSON-lines event journal + periodic JSON snapshot** in `~/Library/Application Support/Lupy/` (human-readable), with per-line checksum, SHA-256 hash chain, torn-tail recovery, idempotent event IDs, schema versioning + migration hook. | Satisfies audit trail, crash safety, idempotency, portability and readability with zero dependencies, fully testable in the sandbox. SQLite was considered (directive suggests "after validation"): it cannot be exercised in the sandbox and adds a C API surface to the untestable shell. Data volume for one founder (thousands of tasks) fits in memory. Revisit if search/scale needs grow. | ACTIVE | Moderate (export/import format is stable JSON) |
| D-005 | Secrets only in macOS Keychain (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, not synchronizable). The core never receives API keys: provider requests carry an auth *placement* and the shell injects the key at send time. | Directive §9; prevents keys from reaching logs, events, backups, prompts. | ACTIVE | Easy |
| D-006 | Cloud models only, provider-neutral adapters: OpenAI, Anthropic, Google Gemini, and OpenAI-compatible endpoints (DeepSeek, OpenRouter, Groq, Mistral…). No local inference, no Ollama, no FluidAudio/Parakeet. Lupy remains usable with no provider (heuristic planner, manual flows). | Founder constraint (8 GB M1, ~1 GB headroom, no local LLM). | ACTIVE | Easy |
| D-007 | Policy/approval gate enforced in code (`PolicyEngine`) outside model text. Standing approvals can only be created by a founder-originated command; model/worker/web-originated content can only *propose* actions. | Directive §9, requirements §11. | ACTIVE | Hard (safety-critical) |
| D-008 | Worker reliability = transparent rule-based counters per worker × task kind (no opaque score); affects only verification strictness/oversight, never permissions. | Requirements §6. | ACTIVE | Easy |
| D-009 | Original character "Lupy" (a small wolf pup drawn in code), original name and icon; no Coucou sounds (macOS system sounds by name only). | LICENSE-ASSETS.md reserves Mochi/Coucou assets; it explicitly invites forks with their own name/icon/character/sounds. | ACTIVE | Easy (founder may seek written permission from Coucou's author to use Mochi — not assumed) |
| D-010 | macOS deployment target **14.0** (Sonoma). | Founder's M1 supports 14–26; 14 keeps `@Observable`, `MenuBarExtra`, modern SwiftUI while maximizing compatibility. Coucou targets 15.0. | ACTIVE | Easy |
| D-011 | Distribution: unsigned-by-Apple, **ad-hoc signed** `.app` in a `.zip` built on a GitHub macOS runner (or by the founder's Mac with one script). No Developer ID / notarization (requires paid Apple membership — not purchased). First launch needs System Settings → Privacy & Security → "Open Anyway". | Directive §10: no purchases without approval; honest Gatekeeper limitations. | ACTIVE | Easy (add Developer ID later) |
| D-012 | Test harness = small custom runner (Coucou-style standalone test binaries), because XCTest/swift-testing are unavailable in the WASM toolchain (no XCTest module, no macros). Same tests run natively on macOS via `swiftc`. | Parity between sandbox and Mac. | ACTIVE | Easy |
| D-013 | Speech input = Apple Speech framework (on-device recognition requested when supported), transcript always shown for review before sending. | Requirements §13.3; avoids heavy local models; data flow disclosed. | ACTIVE | Easy |
| D-014 | Lupy's own licence: **not chosen by the agent** — repository stays private, "All rights reserved" pending founder decision. Coucou-derived code keeps its MIT notice (THIRD_PARTY_NOTICES.md). | Licensing the founder's IP is the founder's decision. | ACTIVE | Easy |
| D-015 | App target compiles in **Swift 5 language mode with minimal concurrency checking**; LupyCore itself is verified under Swift 6 strict concurrency in the sandbox (and natively on the runner). | The app shell can only be compiled on scarce macOS runners; strict-concurrency diagnostics in AppKit/Speech/URLSession glue are the most likely source of first-build failures. UI work is kept on the main actor by design (`@MainActor` models, `Task { @MainActor in }` hops). Revisit (move to Swift 6) once a Mac build loop exists. | ACTIVE | Easy |
| D-016 | Regular Dock app + notch island + menu-bar item (Coucou is menu-bar-only). | A non-technical founder needs an obvious way to open Lupy (Dock/Applications) and a full window for plans, approvals and settings; the island keeps Coucou's ambient feel. | ACTIVE | Easy |
| D-017 | Execution strategy: **API-first, native macOS automation as the only fallback**; Safari WebDriver only on demand later; no Playwright, no visual computer control in v1. All actions go through the action ledger with independent read-back verification. | RAM budget (8 GB, ~1 GB free), verifiability, security scope. Comparison in `docs/EXECUTION_STRATEGY.md`. | ACTIVE | Easy |
| D-018 | Delivery = **one single-file artifact behind a direct link**: `upload-artifact@v7` with `archive: false` uploads `Lupy-<ver>-<sha10>-macOS-arm64.zip` (only Lupy.app inside, made with `ditto --keepParent`), retained 90 days. Every build then **downloads that exact file on fresh `macos-14` and `macos-latest` machines** and checks it like a person would (contents, signature, install, launch, quit, relaunch, self-test, Gatekeeper preview) before it is reported. The Coucou MIT notice is bundled inside the app (`Contents/Resources/THIRD_PARTY_NOTICES.txt`). No GitHub Release. | The founder's ZIP was the repository's source code (Code → Download ZIP), and the old artifact was a zip inside a zip. A Release would publish (needs approval; upload host unreachable from the sandbox); uploading the `.app` folder strips executable bits and symlinks. Cost ≈ 7–9 macOS minutes per build. | ACTIVE | Easy |
| D-019 | Never present first-run or other routine UI as a window-attached **sheet**; use in-window overlays. | AppKit refuses `terminate:` while a sheet is attached (SwiftUI sheet windows report `preventsApplicationTerminationWhenModal`), blocking Cmd-Q, menu-bar Quit and log out / restart / shut down. Caught by build #4's download check; fixed in `09c8c75`. Short app-modal dialogs (open/save panels, confirmations) are unchanged. | ACTIVE | Easy |
